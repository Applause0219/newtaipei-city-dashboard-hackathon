# 新北市統計資料庫查詢平台（oas.bas.ntpc.gov.tw）

**命題文件明列的第一個建議來源。** 先前兩輪探勘都卡住，本輪打通。

## 卡住的原因：少送了一個維度，不是介面拒絕返回數值

先前的判斷是「含年齡的報表每個 `Value` 都是 `...`，研判資料值未由該介面返回」。
那個觀察正確，但**歸因錯了**。

報表頁自己的 JavaScript 是這樣組查詢參數的：

```js
$("#options .list[id*='lisComplex']").each(function () {
    var sComplex = ";" + $this.find("option").first().val().substr(0, 5);
    sComplexs += sComplex;
    sCodes += selected2string($this.attr("id")) + ";";
});
$("#axX").val("[Measures]" + sComplexs);
$("#axCode").val(sCodes + checkedValues.join(';'));
```

報表 11843（現住人口之年齡分配）有**兩個**複分類：

| select | 內容 | 代碼前綴 | 選項數 |
|---|---|---|---|
| `lisComplex1` | 年齡組（總計、0_4歲 … 100歲以上） | `P0203` | 22 |
| `lisComplex2` | 性別（計／男／女） | `P0204` | 3 |

先前送出的是：

```
axX    = [Measures];P0203
axCode = P020300001;…;P020300022;010000065000
```

**少了整個性別維度**——`axX` 沒有 `;P0204`，`axCode` 也沒有性別那一段。
伺服器組不出完整的格子，於是回傳骨架並把每個數值填成佔位符 `...`。

補上第二個維度後：

```
axX    = [Measures];P0203;P0204
axCode = <22 個年齡碼>;<3 個性別碼>;010000065000
```

立即取得真實數值。回應也從 33,233 bytes 增為 49,336 bytes。

## 產出

**1,716 列** = 26 個年度 × 22 個年齡組 × 3 個性別。
涵蓋民國 89–114 年（西元 **2000–2025**），新北市全市（`area_code=65000`）。

時序比 `youth_pop_single_age`（2018–2026）長 18 年，
兩者可互補：本 DAG 提供長期趨勢，單齡 DAG 提供精確年齡與行政區粒度。

## 實作上的注意事項

- **維度與日期都從報表頁動態讀取**，不寫死。來源若新增年度會自動納入
- **少於兩個複分類直接拋錯**，因為那必然會回傳全是 `...` 的空表——
  寧可失敗也不要產出看似成功的空資料
- 結果表的**第一格把年份、地區、第一個數值黏在一起**（例如 `2025新北市4,044,831`），
  要先切出結尾的數值再解析
- 解析前斷言「數值個數 == 年齡組數 × 性別數」，版面改變會直接失敗而非靜默對錯格
- 另有對帳：每個年度的「總計/計」必須等於各分齡組「計」的加總
- 26 個年度全部實測回 200 且有資料，沒有需要排除的年度

## 年齡粒度與 18–35 換算

**`apportioned`。** 來源是 5 歲組，18–35 兩端都跨越組界
（15_19 組只要 18、19；35_39 組只要 35），需要分攤。

被分攤的是**人口本身**，依實測屬於誤差約 0.08% 的那一類，
可放心使用（見 `YOUTH_SOURCE_MAP.md` 第十一、十五節的誤差量測）。

## 同一個機制可以打開的其他報表

`lbtGUID` 的 `__EVENTARGUMENT` 對應報表編號，同一套流程可換編號取得：

| 編號 | 報表 |
|---|---|
| 11841 | 現住戶數、人口密度及性比例 |
| 11842 | 戶籍動態 |
| **11843** | **現住人口之年齡分配（本 DAG）** |
| 11844 | 現住人口之年齡結構 |
| 11845 | 十五歲以上現住人口之教育程度_按年齡別分 |
| 11848 | 現住人口之婚姻狀況_按年齡別分_108年以後 |

11845 與 11848 都含年齡別，且與既有的 `youth_education_age_ntpc`、
`youth_marital_status_age_ntpc`（來源 data.ntpc）主題相同但可能年度更長，
值得後續比對。**本 DAG 的 `REPORT_ID` 是常數，改一個字即可切換報表**，
但複分類的組成不同，年齡標籤解析與對帳邏輯要重新確認。
