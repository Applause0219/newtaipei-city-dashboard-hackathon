# 新北市歸化及定居取得國籍人口（單齡年齡）

## 來源驗證

```
https://www.ris.gov.tw/rs-opendata/api/v1/datastore/ODRP072/{民國年度}?PAGE={n}&COUNTY=新北市
```

- 平台：內政部戶政司 RIS OpenData，免驗證；程式請求一律帶瀏覽器 User-Agent。
- 已實測民國 113：帶 `COUNTY=新北市` 時 `responseCode=OD-0101-S`、`totalPage=626`、每頁 2,000 列；民國 112 也可取得。民國 114、115 查無資料。
- ODRP072 是年度端點。DAG 從民國 113 向前、向後探測，連續兩個無資料年度才停止；查無資料是 HTTP 200 + `OD-0102-S`，不能用 HTTP 狀態碼判斷。
- 原始資料是村里級交叉表，欄位為 `statistic_yyy / district_code / site_id / village / origin / sex / age / population`。`age` 是單齡（含 `100歲以上`）。實測 `origin` 六類為：中華民國國民入境核准定居、其他國籍人民核准定居、大陸地區人民核准定居、東南亞籍人民核准定居、港澳居民核准定居、臺灣地區逾12歲未辦出生登記。

## 重要語意界線

**ODRP072 不是一般遷徙／遷入遷出資料。**它是初設戶籍、歸化及定居取得國籍人口的統計，`origin` 是取得／定居來源類別。一般遷入遷出 ODRP002／011／094 已知沒有年齡欄位，不能用來替代本來源，也不能把本 DAG 的數字寫成「所有新住民遷入人口」。

## 轉換與契約

- 每頁抓到後立即以 `district_code[:8]` 篩選既有 29 個新北行政區；非新北列不進記憶體中的聚合器。為應付數千頁的大型端點，頁面以小批次 bounded concurrency 抓取，但每個 response 完成後立即篩選／聚合，不累積全國資料。村里資料只聚合為行政區列，另產生 `65000` 全市列，沒有把村里粒度寫入事實表。
- 年齡只依原始標籤解析為整數區間：單齡 `n歲 -> (n,n)`；開放區間保留 `None` 端；無法解析直接 `raise`，不靜默略過。
- `gender` 是原始人口性別（男／女）；另產生 `total` 合計列。`value_type=count`、`unit=人`。
- 18–35 判定為 **`exact`**：下游直接篩 `18 <= age_lower` 且 `age_upper <= 35`，DAG 不把 18–35 分攤結果固化，保留所有原始單齡列。
- `breakdown` 保留來源類別、來源年度、村里聚合來源與行政區名稱。行政區代碼與 `youth_pop_single_age` 完全一致，可直接 join。

## 必做防護與對帳

- 每一頁只保留新北資料，並在每個來源期別核對：輸入新北資料總數 = 行政區男女輸出總數 = 行政區 `gender=total` 總數 = 全市 `gender=total` 總數；不符直接失敗。
- 未知性別、未知來源類別、未知行政區代碼、未知年齡標籤都直接失敗。數字解析會去除千分位逗號。
- 每次執行以每期新北來源人口總數和其餘期別中位數做 3 倍尺度檢核。未知範圍變更直接 `raise`；目前沒有已確認的壞年度，`KNOWN_BAD_YEARS={}`。

## 觀察與限制

- 輸出列數會因「行政區 × 單齡 × 性別 × 來源類別」交叉表而多於概念指標數；這是聚合後仍保留零值年齡／分類格的來源結構，不是重複計算。村里原始資料可取得，但刻意不輸出村里粒度以免事實表膨脹。
- 18–35 的數字是這個來源定義下「歸化／定居取得國籍人口」的精確年齡切片，不等於所有在臺新住民，也不等於一般遷入人口。
- ODRP072 目前只有兩個可用年度，趨勢判讀很有限；兩年度仍會做 3 倍尺度檢核，任何明顯範圍跳變都直接失敗。

## 未解決事項

- 尚未找到民國 111 年以前或 114 年以後的可用 ODRP072 年度；DAG 每次會重新探測，若 RIS 補發會自動納入。
- 若未來需要涵蓋「一般遷入／遷出」青年人口，必須另找真正帶年齡欄位的來源；不能從 ODRP072 或無年齡的 ODRP002／011／094 推估。

## 表大小：濾除零值列

來源是 **村里 x 單齡 x 性別 x 定居原因** 的完整交叉表。
民國 112 年新北市 1,250,784 列來源資料，實際只對應 **4,039 人**——
聚合到行政區後仍有 54,540 個組合，絕大多數是 0。

```
                    修改前      修改後
全表列數           109,080       8,895
```

**縮小約 12 倍，而對帳總額與 18-35 歲數字完全不變**
（112 年 4,039、113 年 4,223；18-35 歲 615、761）。

濾零在**逐期對帳通過之後**才執行，所以對帳驗證的是未刪減的完整集合。
0 對總和沒有貢獻，下游一律 `GROUP BY ... SUM(value)` 也不受影響。
`reconciliations` 記錄 `emitted_rows` 與 `emitted_rows_nonzero`，
讓丟棄量可追蹤。

唯一的可見差異：「臺灣地區逾12歲未辦出生登記」在 18-35 歲全期皆為 0，
濾零後該類別的列會消失。這是預期行為，不是資料遺失——
需要顯式零的視覺化應在查詢端 `LEFT JOIN` 維度表補零。

## 範圍確認：`national` 與 `ntpc` 相等不是 bug

日誌每一頁都顯示 `national=N, ntpc=N`。這不是篩選器失效，
而是因為請求本身就帶了 `COUNTY=新北市` 參數，伺服器端已完成篩選。
`_area_code()` 是第二道保險：遇到未列入契約的 `65000*` 代碼會直接拋錯，
其他縣市代碼則丟棄。兩道機制並存，即使來源哪天不再支援 `COUNTY`
參數，也不會靜默把全國資料當成新北市。
