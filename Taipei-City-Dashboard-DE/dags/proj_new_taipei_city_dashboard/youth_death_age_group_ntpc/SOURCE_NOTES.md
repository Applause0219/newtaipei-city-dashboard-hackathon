# 新北市死亡人數（按年齡組、性別）

## 來源驗證

- 資料頁：<https://data.ntpc.gov.tw/datasets/0a5a1e6e-8c91-4c74-b23e-117537180618>
- API：<https://data.ntpc.gov.tw/api/datasets/0a5a1e6e-8c91-4c74-b23e-117537180618/json?page={page}&size=1000>
- 實測 HTTP 200；page 0 有 19 列，其中 18 列是 2006–2023、1 列為全空列；page 1 為空陣列。全空列會被明確計數後丟棄，部分空列則直接 raise。
- 資料頁主要欄位說明對應 `field1` 為年、`item value2/3` 為 0 歲總數男女、`item value6–17` 為 1–4、5–14、15–24、25–44、45–64、65 歲以上的男女計數。
- 實跑產出 252 列：18 年 × 7 年齡組 × 2 性別，期間 2006–2023，area_code 固定為 `65000`（新北市全市）。不補造來源未提供的 2024 年。

## 年齡與 18–35 判定

判定為 **apportioned**。`15–24` 同時包含 15–17，`25–44` 同時包含 36–44；18–35 只能在查詢階段按明確方法處理，DAG 不固化分攤結果。這是死亡計數的行為分攤，不能宣稱與人口加權等同，亦沒有把任何 rate 按人口比例縮放。

所有輸出年齡均是整數區間：`0歲 → (0,0)`、`1_4歲 → (1,4)`、`65歲以上 → (65,None)`。來源沒有單齡資料，未能拆開的部分不推估。

## 欄位陷阱與對帳

- `item value4/5` 是 0 歲的「新生兒」細分，與 `item value2/3` 的 0 歲總數重疊；若一起加總會重複。`item value18–21` 是平均／中位數，不是計數，也不放進死亡年齡組事實表。
- API 欄位採無語意名稱，程式依資料頁語意別名解析；角色找不到唯一欄位會 raise。
- 每年度、每性別的七個輸出年齡組總和，必須等於來源同一性別的七個輸入計數欄位總和；每一來源欄位也逐欄對帳。任何不符直接失敗。
- 每次執行以年度死亡年齡組總量做尺度防護；與其餘年度中位數相差超過 3 倍直接 raise。`KNOWN_BAD_YEARS` 目前為空，沒有已知壞年度可排除。

## 未解決事項

這份 5 歲以上年齡組資料與戶政司 `youth_death_single_age_ntpc` 的單齡資料主題重疊；本支的價值在於提供 2006 起的長期年齡組序列，並可和單齡來源交叉檢核。要得到精確 18–35，仍應優先使用單齡來源。
