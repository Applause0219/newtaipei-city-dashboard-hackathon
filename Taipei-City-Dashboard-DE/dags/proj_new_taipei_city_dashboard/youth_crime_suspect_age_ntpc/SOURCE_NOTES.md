# 新北市犯罪嫌疑犯統計（按年齡）

## 來源驗證

```text
https://data.ntpc.gov.tw/api/datasets/2fdff679-af9c-46ab-bd2b-4555d24163c6/json?page={page}&size=5000
```

- 平台：新北市資料開放平臺，資料集免驗證。
- 欄位：`year`（民國年）、`age`、`item`、`total`、`men person`、`female person`。
- 取得方式：從 `page=0` 開始逐頁抓取，直到空頁；每次請求都帶瀏覽器 User-Agent。
- 來源地圖先前記錄年度 105–110；本次驗證器以活來源分頁抓取時，實際回傳年度已擴到 105–114，應以每次執行的 API 回應為準，不把年度寫死。
- 本 DAG 的 area_level 固定為 `city`、area_code 固定為 `65000`；來源沒有行政區欄位。
- 本次驗證實抓 9,620 筆來源列，轉成 **28,860 列**（每筆來源的 male、female、total
  各一列），涵蓋西元 2016–2025。民國 114 的全年齡全罪名 `total=428,284`，
  明顯高於前幾年序列；DAG 不平滑、不縮放，保留來源值，這個突增仍待資料提供者釐清。

## 年齡處理與 18–35 判定

來源年齡組解析為整數區間：

| 原始標籤型態 | age_lower | age_upper |
|---|---:|---:|
| `00-05歲嫌犯數` 等區間 | 0 | 5 |
| `70歲以上嫌犯數` | 70 | `None` |
| `年齡不詳嫌犯數` | `None` | `None` |
| `總計` | `None` | `None` |

`年齡不詳嫌犯數` 不是可分攤的年齡組，保留原始 `age_band_raw`，並以
`crime_suspect_unknown_age_*` 指標保存；`總計` 也保留原始標籤，以
`crime_suspect_all_age_*` 指標保存。任何不是上述已知型態或可解析區間的標籤都直接拋錯，
不准靜默略過。

18–35 的判定是 **`apportioned`**，不是 exact：

- `18-23` 與 `24-29` 完整落在 18–35；
- `30-39` 跨過 35，只能在查詢端取 30–35；
- 若查詢端採均勻假設，行為計數只能取 `30-39 × 6/10`，這是分攤假設，不是來源直接觀測值；
- 下界 18 恰與警政統計的成年分組界線一致；
- `value_type` 是 `count`，絕不把它當 rate，也不依人口比例縮放成 18–35。

## 罪名階層與輸出指標

`item` 實際含 `總計`、多個以 `總計` 結尾的罪名階層合計，以及個別罪名。
為避免把階層合計和明細相加，DAG 依 `age_scope`／`item_scope` 分成不同 indicator_id：

- `crime_suspect_count`：年齡組 × 個別罪名；
- `crime_suspect_category_total_count`：年齡組 × 罪名階層合計；
- `crime_suspect_all_item_count`：年齡組 × 全罪名總計；
- 另有 `unknown_age`、`all_age` 對應的三組合計指標。

`breakdown` 保存 `crime_item`、`item_scope`、`age_scope` 與原始年齡標籤。
做「全部罪名」或「全部年齡」彙總時只能選一個明細／合計層級，不能把九種 indicator_id 混加。

## 對帳與陷阱

- 對每筆來源列都檢查 `total` 是否等於 `men person + female person`。本次活來源驗證發現
  民國 113 有 **9 筆**不相等（例如偽造文書印文 18–23 歲為
  `total=14、men=51、female=65`）。這是來源資料品質異常，不把任一欄擅自當正確答案，
  三個來源值原樣輸出並在執行 log 警告；`gender=total` 對帳仍以來源 `total` 為準。
- 每個民國年度，`gender=total` 的輸出總和必須等於該年度輸入 `total`，且每筆來源列輸出 male、female、total 三列；對帳檢核留在 DAG 每次執行。
- 計數轉換會移除千分位逗號。
- 不使用 HTTP 以外的頁面總數判斷，必須持續分頁到空頁；來源資料更新後年度或列數改變時，DAG 仍會抓完整資料。

來源中也有同一年度／年齡出現兩列 `item=其他` 的情況，故 `breakdown` 另存
`item_occurrence`，避免兩筆原始列在下游完全不可區分。

## 未解決

- 來源只有年齡組，不提供單齡嫌犯數；30–39 的組內行為率是否近似均勻無法由本表驗證，18–35 分攤應標示低信心。
- `item` 的階層由來源標籤的 `總計` 命名辨識，未取得另一本罪名分類碼表；若來源改用其他合計字樣，DAG 會把它視為新明細，需先人工確認後更新規則。

## 民國 114 年度已排除：數值是全國規模，不是新北市

### 診斷過程

初版 DAG 直接把 114 年度吃進去，會讓儀表板畫出一根 11.5 倍的假尖峰。實際查證：

| 民國年 | 全年齡全罪名 total |
|---|---|
| 111 | 28,714 |
| 112 | 35,707 |
| 113 | 37,221 |
| **114** | **428,284** |

三項證據指向「範圍或口徑改變」而非資料損壞：

1. **內部自洽。**114 的 `men person` 321,171 + `female person` 107,113 = 428,284，
   且「總計列」與「分齡加總」完全相等（十個年度皆然）
2. **年齡結構幾乎不變。**同形狀、不同量級：

   | 年齡組 | 112 | 113 | **114** |
   |---|---|---|---|
   | 18-23 | 11.0% | 12.3% | 11.3% |
   | 24-29 | 13.3% | 14.9% | 13.2% |
   | 30-39 | 21.4% | 21.2% | 21.2% |
   | 40-49 | 23.9% | 22.7% | 22.9% |

3. **比例對得上人口佔比。**`37,221 / 428,284 = 8.7%`，
   而新北市人口約佔全國 9%

**研判：來源誤將全國數字放進新北市資料集。**
新北市人口約 400 萬，一年 42.8 萬名嫌疑犯等於全市 10%，不可能。

### 處理方式

`KNOWN_BAD_YEARS = {114: ...}` 明確排除，並在排除時印出訊息。
來源澄清後移除該設定即可自動納回。

同時加了一道通用防護 `drop_scope_anomalies()`：
任何年度的全年齡全罪名 total 若與其餘年度中位數相差超過 3 倍，**直接拋錯**。
已知的壞年度走排除清單，**未知的新異常一律 fail loud，不許靜默入庫**。

實測結果：排除後保留 8,658 / 9,620 列，涵蓋民國 105–113 共 9 年，
各年度對帳（輸入 total == 輸出 total）全數通過。

### 另一個保留但未修正的問題

來源有 **9 筆 `total != men person + female person`**，全部在民國 113，例如：

```
18-23歲 / 偽造文書印文  total=14,  male=51,  female=65
30-39歲 / 毀棄損壞      total=22,  male=132, female=154
50-59歲 / 妨害自由      total=330, male=26,  female=70
```

其中有 `male > total` 的情形，數學上不可能，應是來源欄位錯位。

**刻意保留原值不自行修正**——我們無法知道哪一欄才是對的，
猜測性修正會製造出看似合理、實際無法辯護的數字。
ETL 會印出警告，這 9 筆在下游使用時需自行判斷。
